1. Prinsip desain yang dipakai

Hermes sendiri menggunakan skill sebagai dokumen pengetahuan on-demand dengan progressive disclosure dan kompatibel dengan standar Agent Skills. Skill lokal berada di ~/.hermes/skills/; Hermes juga mempunyai skill management dan dukungan MCP. Karena itu arsitektur terbaik adalah agent/division sedikit, skills banyak tetapi hanya dimuat ketika dibutuhkan.

Agent = tanggung jawab
Dipisah bila perlu independence, permission boundary, atau konteks kerja berbeda.
Skill = SOP/keahlian
Prosedur reusable yang dimuat hanya ketika relevan.
Tool = bukti deterministik
Compiler, test runner, linter, scanner, Git, Playwright, Semgrep, CodeQL, Trivy.
Gate = keputusan
PASS/FAIL yang berbasis evidence, bukan “feeling” LLM.
Rule: jangan membuat agent baru jika masalah dapat diselesaikan dengan skill atau tool pada agent/divisi yang sudah ada.
Security boundary rule: approval prompts, output redaction, skill scanners dan tool allowlists adalah defense-in-depth, bukan containment absolut. Untuk untrusted content gunakan OS-level/whole-process isolation. Jalankan agent non-root, mount hanya workspace yang diperlukan, minimalkan network egress dan jangan expose host secrets.

4. Reverse Engineering & Reconstruction Division

Divisi ini memberi Super Dev Builders dua jalur produksi: Build From Specification dan Authorized Reconstruction From Existing Target. Tujuannya bukan membobol proteksi, tetapi memperoleh observasi seteliti mungkin dari surface yang sah, membangun evidence package, lalu merekonstruksi behavior/UX/functionality tanpa mengarang komponen yang tidak diketahui.

Hard boundary: divisi ini tidak boleh bypass authentication/authorization, CAPTCHA/anti-bot/access controls, paywall, rate limit, DRM/licensing, code-signing, certificate pinning, secret/credential controls, atau mengeksploitasi vulnerability untuk memperoleh akses. Tidak boleh mengambil private source/data/API yang tidak diotorisasi. Jika target membutuhkan akses lebih dalam, Owner harus menyediakan source/binary/test account/staging environment/credentials dan scope authorization secara eksplisit.

4.1 Dua mode resmi

ModeInputBolehTidak boleh
A — External ReconstructionURL publik / aplikasi yang dapat diamati secara sah.Public crawl, browser automation, DOM/layout/assets, screenshots, responsive states, public network behavior, public API contract, technology signals, accessibility/performance, user-flow observation.Bypass login/access control/anti-bot, credential theft, private endpoint discovery by exploitation, source-code theft.

4.5 Network observation policy

Browser DevTools/Playwright trace adalah pilihan pertama. Proxy/interception tooling hanya digunakan di Mode B pada aplikasi/environment yang Owner otorisasi dan tidak untuk mematahkan TLS/certificate controls pihak ketiga. Jangan menyimpan authorization headers, cookies, tokens atau PII ke artifact reconstruction; lakukan redaction sebelum evidence masuk ke context LLM.

6. Kebijakan keamanan skills & MCP

Tidak ada skill pihak ketiga yang dapat dijamin “100% aman” hanya karena populer atau open-source. Karena skill dapat menginstruksikan agent menjalankan shell/script, membaca file, atau mengubah konfigurasi, ia adalah bagian dari software supply chain.

NEW SKILL / MCP
      │
      ▼
SOURCE TRUST CHECK
official/vendor > established security org > community
      │
      ▼
PIN VERSION / COMMIT
      │
      ▼
STATIC READ + SKILL-SCANNER
      │
      ▼
CHECK scripts / hooks / network / permissions / secrets
      │
      ▼
TEST IN SANDBOX / DISPOSABLE REPO
      │
      ▼
ALLOWLIST MINIMUM TOOLS
      │
      ▼
APPROVE → INSTALL
      │
      ▼
PERIODIC RE-AUDIT ON UPDATE

Hermes mendokumentasikan defense-in-depth: dangerous-command approval, file-write controls, MCP credential filtering, context-file prompt-injection scanning, cross-session isolation, secret redaction dan sandboxing. Namun Hermes juga menegaskan bahwa OS-level isolation adalah security boundary yang sebenarnya terhadap adversarial LLM. Terminal-backend sandbox mengurung shell/file operations, tetapi tidak otomatis mengurung seluruh plugin/hook/MCP/agent-process path.

Production/untrusted-input baseline: gunakan whole-process wrapping (mis. official Hermes Docker/Compose atau supported whole-process sandbox), non-root user, workspace-only mounts, restricted egress, no Docker socket, no host SSH/AWS/Kubernetes credential mounts, dan credential injection minimum. Default local backend hanya untuk trusted development.
Dilarang auto-approve: destructive shell, production deploy, database destructive migration, secret/credential change, IAM change, publish/release, payment/financial action, deletion, atau MCP baru yang meminta broad filesystem/network access.

MCP policy: gunakan official/vendor MCP bila tersedia; expose hanya tool yang diperlukan dengan include/allowlist; filesystem hanya pada workspace allowlist; production database default read-only; credential scope minimum. Hermes memfilter environment stdio MCP, tetapi credential yang secara eksplisit dikonfigurasi tetap dapat dibaca MCP tersebut—karena itu treat MCP server sebagai trusted code dan audit source/version-nya.

8. Token & PC Resource Policy

  1. Sequential by default. Maksimum 1–2 specialist aktif; parallel hanya untuk task independen yang benar-benar menghemat waktu.
  2. Progressive disclosure. System prompt hanya memuat nama/deskripsi skill; full SKILL.md/reference dimuat saat triggered.
  3. Artifact handoff. Requirement, ADR, plan, diff, test/SARIF report; jangan forward seluruh transcript.
  4. Diff-first review. Reviewer menerima requirement + Git diff + file terkait.
  5. Tool before model. Compiler/linter/test/scanner menjawab fakta deterministik.
  6. Bounded loops. Maksimum 2–3 repair cycles, lalu eskalasi; cegah infinite token loop.
  7. Cheap model for routine. Routing/docs/simple transforms; strong model untuk architecture, complex debugging, security triage dan final audit.
  8. No duplicate skill families. Pilih satu primary methodology; skill kedua hanya sebagai specialist.
Rekomendasi audited: jadikan workflow Hermes-native sebagai control plane; gunakan konsep Superpowers sebagai methodology hanya setelah compatibility/security gate. Tambahkan external skills secara selektif: Anthropic untuk frontend/web testing/MCP, Trail of Bits untuk audit/security, Sentry untuk secondary code/skill review dan observability bila relevan. Jangan install satu repository penuh jika hanya satu skill yang diperlukan.

9. Prioritas instalasi — jangan install semuanya sekaligus

Phase 1 — Foundation (Audited)

Mulai dari Hermes builtin/official skills dan Plan Mode. Gunakan hermes skills browse --source official, hermes skills inspect ..., dan hermes skills audit. Prioritaskan official software-development skills yang benar-benar dibutuhkan seperti ast-grep, grill-me, rest-graphql-debug, code-wiki, dan subagent-driven-development bila tersedia pada versi Anda.

Superpowers: methodology-nya tetap sangat baik sebagai referensi (brainstorming, plan, TDD, debugging, review, verification), dan upstream mendokumentasikan hermes plugins install obra/superpowers --enable. Namun audit V2.1 menemukan laporan aktual bahwa instalasi pada Hermes v0.20.4 dapat diblokir Skills Guard sebagai dangerous verdict. Karena plugin memiliki surface lebih besar daripada SKILL.md biasa (hooks/scripts/plugin code), jangan bypass scanner dan jangan menjadikannya mandatory install sampai kombinasi versi Anda PASS. Jika gagal, port/adapt hanya workflow yang dibutuhkan menjadi custom Hermes skills yang kecil dan diaudit.

Phase 2 — Assurance

Adopsi/audit Trail of Bits: audit-context-building, differential-review, Semgrep, CodeQL, SARIF, variant-analysis. Untuk PC terbatas, Semgrep menjadi frequent fast scan; CodeQL dipakai pada milestone/release atau area berisiko tinggi karena lebih berat.

Phase 3 — UI & Integration

Anthropic: frontend-design, webapp-testing, mcp-builder. Karena ini dibuat untuk ekosistem Agent Skills, lakukan compatibility test di Hermes sebelum production use.

Phase 4 — Governance

Sentry getsentry/skills: skill-scanner, security-review, agents-md, code-simplifier dapat dipakai sebagai secondary methodology. Primary quarantine gate tetap Hermes Skills Guard / hermes skills audit, ditambah manual source review.

Phase 5 — Deterministic Security Tools

Semgrep, CodeQL, Trivy; Syft bila membutuhkan SBOM. Pin versi dan update terkontrol. Jangan menambah scanner hanya karena tersedia—overlap menghasilkan noise dan maintenance.

11. Rekomendasi final

Super Dev Builders Ecosystem bukan “sebanyak mungkin skills”, melainkan curated skills + specialized divisions + authorized reconstruction + strong gates + deterministic verification.

Reverse Engineering & Reconstruction menjadi capability resmi, tetapi dipisahkan dari Security/Pentest. Tujuan utamanya adalah understand → specify → rebuild → compare, bukan defeat controls. External target memakai Playwright-first safe observation; MobSF/JADX/Apktool/Ghidra hanya lazy-loaded untuk owner-authorized deep analysis.

Core methodology: Hermes-native workflow/Plan Mode + curated Superpowers methodology (plugin hanya jika security scan PASS). UI/testing/MCP: audited Anthropic Agent Skills. Security & deep audit: audited Trail of Bits skills + deterministic scanners. Skill supply-chain/code quality: Hermes Skills Guard first, Sentry skills second. Observability: current getsentry/sentry-for-ai bila Sentry dipilih. Repository integration: official GitHub MCP dengan minimal tool exposure. Current library docs: Context7 bila dibutuhkan dan telah diaudit. Runtime security: whole-process isolation + least privilege untuk untrusted/production workloads.

Code Audit & Engineering Assurance menjadi otoritas final teknis sebelum release gate, tetapi tidak menggantikan QA atau Security. Ia menggabungkan evidence dari seluruh divisi dan memeriksa kesehatan engineering secara sistemik.
