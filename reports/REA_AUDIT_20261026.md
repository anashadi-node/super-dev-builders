## 7. Keterbatasan & risiko yang harus dibawa ke operasi

1. **Node tidak sesuai deklarasi paket.** `engines`: `^22.23.4 || ^24.22.1 || >=26.12.1`; host punya
   **26.7.0** → `rea doctor` menandai `missing_dependency`. Faktanya CLI + MCP + analisis JS berjalan normal
   (`--version`, handshake, analisis 1,83 s). Status: **diterima sebagai risiko tercatat**, bukan diabaikan;
   bila muncul kegagalan aneh, langkah pertama = pasang Node 24 LTS terisolasi untuk REA.
2. **Engine analisis native belum ada**: `ghidra` (`GHIDRA_INSTALL_DIR` kosong), `ida`, `jadx`, `hopper`.
   Artinya decompile native/APK/Objective-C **belum** bisa dipakai. Yang sudah terbukti jalan hari ini:
   analisis JavaScript/Electron statis, web capture, PE/artefak statis, EVM bytecode (`evmole`).
   Pemasangan Ghidra/JADX = pekerjaan terpisah, butuh approval (ukuran & lisensi), tidak dilakukan di audit ini.
3. **Maintainer tunggal + 1.093 issue terbuka** → risiko keberlanjutan, bukan risiko keamanan. Mitigasi: pin
   versi + integritas, upgrade hanya lewat audit ulang.
4. **`licenses/GPL-3.0.txt` ada** di paket (katalog notice, mis. komponen pendamping). MIT proyek tetap
   berlaku untuk kode REA. Kita **tidak** meredistribusikan paket ini, hanya memakainya di host → kewajiban
   copyleft tidak menyebar ke kode SDB. Jangan pernah menyalin berkas REA ke dalam repo SDB.
5. **Kapabilitas = risiko**: `execute_rizin_command`, `debug-with-gdb`, `install_adb_package`, frida opsional,
   PTY, `isomorphic-git`. Semua dipakai hanya di bawah scope yang diotorisasi (§8).
